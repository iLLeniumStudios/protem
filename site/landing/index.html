Kubernetes access that ends on its own.

Ask for a role for a few hours. An approver decides, and the access is removed when the time is up, on every cluster.

Git first.

Who may request which role, where, and who approves are resources you keep in Git. The UI steps back for anything Argo CD, Flux or Helm manages.

profiles/payments-edit.yamlManaged by Argo CD
kind: AccessProfile
metadata:
  name: payments-edit
spec:
  role: { kind: ClusterRole, name: edit }
  namespaces: [ payments ]
  duration: { default: 1h, max: 2h }
  approval:
    rules:
    - { name: prod-needs-sre, mode: Manual, requiredApprovals: 1 }
In the UI: “Managed by Argo CD. Change it in Git; edits here would be reverted.”

The cluster owner sets the limit.

An agent binds only the roles its own cluster allows, whatever the hub asks for.

Plain RBAC.

A grant is an ordinary RoleBinding. No authorization webhook and no API server flags, so it does not depend on control-plane access.

$ kubectl get rolebindings -n payments -l protem.dev/managed-by NAME ROLE AGE protem-grant-protem-system.grant-alice-payments-edit ClusterRole/edit 12m $ kubectl auth can-i update deployments -n payments --as alice@company.com yes

How it fits together

Everything is a Kubernetes resource on one hub, with no database. Agents pull from the hub; the hub never reaches into your clusters.

Defined in Git

A profile is a Kubernetes resource on the hub. It says which role can be requested, on which clusters, by whom, for how long, and who approves; there is no database behind it.

Keep profiles in Git and let Argo CD, Flux or Helm apply them. The UI shows anything they manage as read-only.

Read the guides

prod-view.yaml 
apiVersion: protem.dev/v1alpha1
kind: AccessProfile
metadata:
  name: prod-view
  namespace: default
spec:
  displayName: Production read-only
  role:
    kind: ClusterRole
    name: view
  scope: Namespaced
  namespaces:
  - default
  clusters:
    selector:
      matchLabels:
        env: prod
  duration:
    default: 30m
    max: 1h
  requesters:
    groups:
    - devs
  justification:
    reason: Required
    ticketPattern: "^INC-[0-9]+$"
  approval:
    rules:
    - name: prod-needs-sre
      mode: Manual
      approvers:
        groups:
        - sre-leads
      requiredApprovals: 1

Install

Install the operator on your hub cluster with Helm. Replace <version> with a released chart version.

Shell 
helm install protem oci://ghcr.io/illeniumstudios/charts/protem \
  --version <version> \
  --namespace protem-system --create-namespace
