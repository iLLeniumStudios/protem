# Protem web UI redesign

Goal            A person gets the elevation they need, or decides on someone else's, in under a minute, and can always see exactly what access is live, where, and until when.
User and task   Requester (protem-user): find the right profile, ask with a reason, watch it go live, give it back early.
                Approver (protem-approver): see what is waiting, understand exactly what is being asked (profile, clusters, namespaces, duration, reason, ticket, approvals still needed), decide.
                Admin (protem-admin): see the fleet's state of elevation: what is live where, cluster health, and the audit trail.
Deliverables    App shell with role-aware navigation and URL routes, on one shared token theme (light + dark):
                1. My access (everyone): live grants with time left and Revoke; my requests and their state; entry to Request access.
                2. Request access: profile catalog → request form (clusters, duration ≤ profile max, ticket, reason).
                3. Approvals (approvers, admins): queue → request detail with scope, per-cluster requirements progress, decision history; Approve (optional comment) / Reject (reason required).
                4. Request detail and grant detail (deep-linkable): timeline, scope, per-cluster enforcement state, revocation.
                5. Fleet (admins): cluster health, heartbeat, agent version, live grants per cluster.
                6. Audit (approvers, admins): filterable, sortable event table.
                7. Overview (admins' landing): live grants across the fleet, waiting approvals, unhealthy clusters.
Lead            Requester: the live grant and its time left; with none live, the catalog. Approver: the oldest waiting request. Admin: anything abnormal (unhealthy cluster, waiting request), else live grants.
Content reality Zero / one / many for grants, requests, approvals, clusters and audit events; audit grows to hundreds of rows. Long strings: profile names, emails, ticket IDs, namespace lists, cluster names. All data is real from the API; no placeholder numbers.
Irreversible    Reject (ends the request), Revoke (removes live access early), Cancel request. Each confirms in a dialog that names what happens; reject needs a reason; destructive wears the danger variant on trigger and confirm. API failures show the server's message and keep the user's input.
Theme           New: character "trustworthy", brand #1D5FA8 (generated by `ai-design-check system`, every text pair checked at WCAG 4.5:1 in both modes). Light and dark, follows the OS, with a toggle. Fonts Public Sans (UI, tabular numerals) + IBM Plex Mono (identifiers), bundled locally: the UI ships inside the operator binary and must work with no internet.
Platform floor  320 px (approvers act from phones). React 18 + Vite + Tailwind 3 + Radix primitives. WCAG 2.2 AA. No RTL.
API             Allowed to change. RequestView gains clusters, namespaces, per-cluster requirements with approvals so far, and grantRef; /api/me reports whether dev personas are enabled so the persona switcher only appears in dev.
Out of scope    Auth/OIDC flows, profile/cluster editing (CRDs stay the source of truth), notifications, i18n.
Assumptions     Persona switcher stays as a dev-only tool → hidden unless dev auth is on (cost if wrong: one flag).
                3 s polling stays → no websocket work (cost if wrong: stale data up to 3 s).
                react-router for URLs → deep links for approvers (cost if wrong: one dependency).
                Audit visible to approvers and admins only in navigation; the API decides what data each role gets.
Done when       `npx @enmera/ai-design-check` 0 errors (src); `scan` and `narrow` 0 errors on every screen in both themes and at 320 px;
                XIAS render gates pass on snapshots (axe, states, target size, responsive, overflow, spacing, reduced motion, intent, screen economy);
                keyboard/interactive gates pass on the live page; `go test ./internal/...` and `bun run build` green;
                `/critique` returns no rework.
